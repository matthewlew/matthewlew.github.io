Tags, chips & inline status

All of these are live components from lds.css, built on the same One Token engine: a status modifier sets meaning, an emphasis class sets tone, and every color — including the --icon token — resolves off the shared --c-* scale. Below, how the pieces differ and when to reach for each.

Tag vs. banner same semantic, different scale

Same status, same class shape — lds-tag--error and lds-banner--error. The meaning lives on the component; both point at the same hue through the one status map in lds.css, so they can never drift apart. What differs is scale: the tag is an inline status pill and takes the soft tone, the banner is a block-level message and stays subtle, because a large field needs less saturation to register. Reach for a tag to label a row or field; a banner to speak to the whole view.

Inline status .lds-inline · no container

For form validation and inline feedback: a hue icon + hue label, no background. Icon uses currentColor, so it is the exact same color as the text — they read as one unit.

Tag tones soft (default) · plain (outline)

Two tones for read-only status. Soft is the everyday tonal fill. Plain is a white chip with a hue border and hue label — quieter, for dense tables. (Solid mid-hue fills are dropped: white-on-500 goes murky on warm hues, and 500 is a graphic-fill step, not a text-background step.)

Chips .lds-chip · interactive

Tags describe; chips do. A chip is the interactive counterpart — filter, dropdown, or removable input token. Neutral by default with a real hover and pressed step (shown below), and a filled selected state. Selected uses a grey-900 knockout — clean contrast, unlike a murky mid-hue fill.
