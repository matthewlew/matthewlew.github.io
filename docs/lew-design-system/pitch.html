The look-and-feel calls

Three decisions, my recommendations.

You asked the right questions. Here's where I'd land — and why. All three are theme-level, so a project can override any of them.

Q1

Fill, outline, or ghost buttons?

REC · Outline default + Fill for primary CTA
Fillbold
Order now
High emphasis, unmistakable CTA. Reads loud — use it for the ONE primary action per view.
Outline✓ default
Order now
Quiet, editorial, on-brand with your portfolio's flat 1px language. The system default; pairs with one fill CTA.
Ghosttertiary
Order now
Lowest weight — tertiary actions, toolbars, icon chrome (palette's ghost-chip lives here).

Not either/or — LDS ships all three as variants. The theme sets the default. Portfolio → outline; Palette → ghost/pill; Product → fill. Never more than one fill per screen.

Q2

Glass UI or very simple?

REC · Simple core, glass as an opt-in theme
Simple · default
Flat, sharp, 1px
Fast, accessible, timeless. Renders identically everywhere. Your portfolio's DNA.
Glass · opt-in
Translucent, blurred
Great over imagery (palette's gradients). Costs blur perf + contrast care.

The core stays simple — flat surfaces, real borders, no blur. That's the reliable, accessible default across all repos. Glass is a theme add-on (a --surface-glass recipe) that image-forward projects like palette opt into. You never pay blur cost where you don't need it.

Q3

What can be themed?

REC · Six knobs, everything else fixed
KNOB 01

Brand hue

An 11-step scale from one hex. Drives all seven color roles via One Token.

portfolio #C8391B · palette #AA3BFF
KNOB 02

Typography

Display + body + mono families. The single biggest personality lever.

DM Sans ↔ system-ui ↔ Inter
KNOB 03

Radius

Corner scale: sharp 0, product 10px, pill 999px. Reshapes every control.

0 ↔ 12 ↔ 999
KNOB 04

Shadow / surface

Flat, soft-elevated, or glass. Sets depth language.

none ↔ soft ↔ glass
KNOB 05

Density

Spacing multiplier — compact tools vs. airy marketing.

0.85 ↔ 1 ↔ 1.15
KNOB 06

Default mode

Light or dark starting point; both always available at runtime.

light ↔ dark

Fixed on purpose: component structure, spacing rhythm, the seven color roles, accessibility rules, interaction states. That's what keeps twelve projects feeling like one system instead of twelve snowflakes.
