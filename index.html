The idea underneath

One Token

Seven object colours, four container classes, zero hardcoded hex. Declare what a colour means, not what it looks like — so brand, dark mode and mixed themes are one class swap, not a rewrite.

Build on it

Starting a new one.

Every project above starts the same way, which is the point of having a system.

  • 01   Take the system npm i @lew/lds — or link the CSS on its own if the project has no build step.
  • 02   Theme at the root Put theme-* and emph-* on the root element. Custom properties inherit downward only, so a theme class on an inner wrapper leaves the page resolving defaults while the components inside look correctly themed.
  • 03   Use the semantic roles --text-title/subhead/body/caption, not the raw --size-* scale. The role carries leading and tracking too; taking only the font-size drifts.
  • 04   Record what you ruled out A change to the system needs an entry in the decision record in the same commit — if it changed what a token means, or set a constraint consumers have to respect.
  • 05   Link back New projects appear in the hub widget on every page, so the set stays navigable from anywhere in it.
