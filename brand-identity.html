Usage Rules05 / 06

Rules.

✓ Do

  • Let red earn its placeReserve the signature red for accents — labels, active states, one rule line. Scarcity is the point.
  • Let the corner carry the eraRadius is a theme knob, not a constant — this theme runs 18px, and the portfolio ran 0px before it. Components never hardcode one.
  • Separate by shadow or by ruleHairlines divide sections; cards lift on a warm, brand-tinted shadow. Card and page sit at the same lightness on purpose.
  • Set metadata in monoDates, tokens, numbers, and labels always use the mono role, --th-mono. It signals machine-readability.

✕ Don't

  • Don't flood with redNever use red as a background fill or for body copy. If it feels loud, there's too much.
  • Don't add shadows or roundingNo drop shadows, no rounded corners, no gradients-as-decoration. It breaks the language.
  • Don't hardcode valuesNever bypass a token with a raw hex. The token is the contract — honor it everywhere.
  • Don't mix type rolesDisplay for statements, sans for reading, mono for data. Don't blur the three.
Innovation Moves06 / 06

System.

▲ 01
Token-first
Every color, size, and rule starts as a named token — never a one-off value.
▲ 02
Machine-readable
Structure that both a designer and an agent can parse and act on.
▲ 03
Semantic layers
Primitive → semantic → component. Meaning travels, values follow.
▲ 04
Governed
Documented rules, versioning, and clear ownership. Systems need law.
▲ 05
Themeable
Light, dark, and brand modes fall out of one architecture for free.
▲ 06
Accessible
WCAG AA is a constraint the system enforces, not an afterthought.
▲ 07
MCP-native
Exposed via protocol so agents can read and build against it live.
▲ 08
Self-documenting
The artifact you're reading is the spec. Brand and system are one.
